# Dependencies and patches

Formal consumers use the Bend and Lean pins in `toolchain.json`; `mise run setup:formal` delegates to `pnpm setup:formal`. Installation downloads the exact platform archive and checks its pinned SHA-256 before extraction. Existing installations are preserved and their selected versions are checked. Development may select an explicit local `MOMENT_BEND_HOME` or `MOMENT_LEAN_HOME`; qualified source and emitted identities remain separate from the operator's tool location. Fresh clones have their own default `.tools` setup and need no sibling checkout. These tools are development/proof dependencies; the distributed runtime executes the included JavaScript without installing them.

When changing a formal pin, inspect the release and backend/ABI changes, refresh its actual platform archive digests, rebuild with `pnpm build:core`, run `pnpm test:proof`, regenerate bindings and run the applicable native and installed-package checks. A new version label alone does not establish source/model correspondence. Preserve a counterexample or an explicit limitation when the model and native behavior differ. The [semantics owner](../reference/semantics.md) defines representation and proof scope.

The manifests and `pnpm-lock.yaml` own JavaScript versions. `packageManager` pins pnpm 12.18.0; `mise.toml` pins the matching pnpm executable and Node.js 26.13.0, which supplies the built-in SQLite binding. TypeScript remains the contract compiler. Ajv 8.20.0 supplies the internal input validator and local JSON Schema compiler. Their execution tests cover shape rejection and schema-reference boundaries; public API admission still requires the kernel and transport integration.

## Setup and updates

Run `mise install`, `mise run setup`, and `mise run check`. The tasks delegate to `pnpm install --frozen-lockfile` and `pnpm check`; the equivalent pnpm commands work when the pinned tools are already on PATH. `mise run test` runs the runtime suite. Keep additional native tools in mise rather than documenting untracked manual installs. Personal overrides belong in ignored `mise.local.toml` files. The optional `mise.secrets.toml` profile is loaded only when the `secrets` environment is selected. [mise configuration](https://mise.jdx.dev/configuration)

Review upstream release notes and compatibility before updating exact pins. Use pnpm for dependency and lockfile changes, then run frozen installation and the affected checks. Do not generate a competing npm lockfile. `pnpm-workspace.yaml` disables implicit dependency repair during script execution and lifecycle scripts during installation; explicitly review any future dependency that requires a build before admitting a narrow exception. Record tool versions and actual results in verification. [pnpm settings](https://pnpm.io/settings)

The project disables mise's automatic upgrade pruning. Do not run global upgrades or prune shared installations as part of project setup. Node changes require actual SQLite reopen, interruption, and competing-writer tests; changing a manifest's engine range alone proves no runtime compatibility. For a new native tool, document its consumer, exact version, installation path assumptions, and meaningful revalidation. Keep agent protocol and sandbox updates coupled to their real integration and boundary checks.

The byte verifier additionally binds its worker source, schema digests, Node version, platform, and permission descriptor. Node, worker, or receipt-format updates need the actual verifier, permission-denial, publication-interruption, daemon-restart, and measured-usage tests. Published schema versions remain immutable; change their versions when their admitted definitions change after release. Restart the local Moment service and publish a fresh matching advertisement for a changed descriptor. Do not upgrade the user's Codex installation as part of this provider maintenance. The provider adds no package or native build dependency beyond the pinned Node runtime.

Codex is an external API dependency, admitted by the particular surface being used. `runtime/codex-api.mjs` owns the consumed app-server response/notification shapes and pre-turn model/permission agreement. Record the observed executable version as provenance; an older, newer, prerelease or unavailable version label alone does not refuse an otherwise working surface. The recorded 0.169.0 baseline identifies executed evidence, not an allowlist or a general compatibility guarantee. Preserve ephemeral authentication, read-only private worker state, disabled tool network, exact model selection, output validation and recovery ownership.

| Surface | Admission and mismatch behavior |
| --- | --- |
| MCP configuration CLI | Exercise `mcp list/get/add/remove` in private staging. Validate consumed JSON and the owned registration before publication; preserve unrelated bytes, ownership and expected-old checks. A command/shape disagreement refuses publication with its boundary and observed version. |
| Native inference | Perform the actual initialize/account/model calls and validate the fields used. Check the requested model, never-approve policy and selected read-only profile or resolved read-only permissions before `turn/start`. Additional fields and unrelated notifications are accepted. The local API contract digest identifies our expectations, not a server-negotiated schema. |
| Submitted native work | Validate acknowledgments, consumed notifications and final output. Missing methods/parameters or required fields produce a bounded diagnostic naming the boundary and observed version/RPC code. Preserve pending work before inference and unknown work after possible submission. Reconcile retained evidence before another attempt; do not retry with different permission/auth/model settings. |
| Lifecycle hooks | Use the concrete event fields and native exact-definition trust. Hook inventory, trust, execution and context delivery are separate observations. Hook failure leaves ordinary conversation available. |
| Historical sources | Check source custody, session identity and recognized message structure. Retain the creation-header version, or explicit unknown, as metadata. A changed consumed message shape is unavailable evidence; unfamiliar release labels with the same structure are accepted. |

Compatibility failures affect the selected feature. Session-memory failure preserves the last valid cache and ordinary Moment operations. Diagnostics contain local boundary descriptions and bounded version/code information, excluding raw account, request and upstream error payloads. There is no automatic developer notification channel. Generated-schema snapshots remain useful explicit verification evidence; runtime inference does not depend on a particular schema-export directory layout. Keep Moment's own store formats, contracts/catalog identity and the Node/pnpm toolchain checks independently enforced.

## Private information

Moment currently has no encrypted private configuration. When a concrete consumer needs private data in Git, use SOPS with age rather than plaintext, including if the repository later becomes public. Select intended owner-controlled public recipients and add a narrow `.sops.yaml` creation rule for `secrets/<purpose>.enc.json` or encrypted YAML. Keep private age identities and recovery copies outside the checkout. SOPS configuration carries public recipients, not private decryption keys. [SOPS configuration reference](https://getsops.io/docs/reference/)

Use `MISE_ENV=secrets mise install` to obtain pinned SOPS 3.13.3 and age 1.3.2 when needed. Before relying on a real encrypted file, test a disposable synthetic encrypt/decrypt round trip and refusal with a wrong key; verify recipient and recovery access for the intended custody separately. Do not copy sibling projects' credentials. Editing, decrypting, or loading a private value must be an explicit operation, with only the consumer's required fields passed to its process. Ordinary checks must not require credentials or decrypt a whole account environment. Keep plaintext, temporary decrypted files, private identities, logs, and captured session material out of Git. Record consumers, rotation, recovery, and remaining live-use checks beside the owning operation.

## Owned patches

There are currently no owned dependency patches. Before adding one, record the upstream version and issue, patch purpose, affected consumers, application mechanism, tests, and removal condition. Keep patches reviewable and scoped; do not hide vendored changes in generated lockfile noise. Rebase or remove them explicitly during an upstream update, and preserve any needed compatibility migrations.

## Release preparation

Before a future release, verify repository privacy and licensing intent, check all advertised methods against implemented ones, run relevant integration and recovery checks, and review migration and rollback procedures. A contract version and a runtime release version are separate. Publishing a package, pushing commits, deploying a daemon, or spending on infrastructure requires the applicable authorization; dependency maintenance itself does not imply those actions.

## Managed installer compatibility

`pnpm test:integration` explicitly invokes the installed read-only Codex CLI in private staging, then exercises owned preview/apply/repeat/removal, exact unrelated-byte preservation, emitted SDK launcher, conflicts, expected-old identity, journal recovery and a killed installer. It is separate from `pnpm check`, which does not invoke Codex. The installer records the observed CLI version and checks its configuration commands in staging, then emits the exact Node 26.13.0 executable and checkout entry; release labels alone do not refuse installation. Couple updates to those tests and the isolated native MCP gate, with no primary configuration, auth cache, token-refresh or binary mutation. Ordinary setup has no account requirement.

Catalog source closure includes package/lock/workspace policy, mise pins, TypeScript configuration, generator sources, declarations and runtime files. Regenerate with `pnpm generate:bindings` after changing those owners. Both checking and runtime startup refuse a stale build. SDK input-schema projection retains exact shared schema documents while kernel admission/fault presentation stays in the authenticated native boundary. Additional SDK validation limits must not replace Moment’s typed faults with unstructured results; keep strict framing and admission bounds together.


## Guidance native profile maintenance

Memory and guidance share `runtime/codex-memory.mjs` for owned process/authentication, API validation and durable native receipts. Memory core prompt 6 clarifies native-focus attribution; native strategy/profile 6 uses compact renderer 2 with unchanged role instructions and result schema; qualified profile 5 completions remain recoverable. These identities have separate owners, and frozen older prompt data remains reconstructable. The separate guidance strategy in `runtime/guidance-profile.mjs` owns profile 1, native output schema, prompt and quote projection. Change the relevant profile identity when its semantics change, and preserve uncertain journal recovery rather than relabeling old output. Release labels remain observations; actual consumed API/model/permission agreement owns compatibility.

Qualify common-engine changes against memory regressions and the source/resource/projection, real owned child, shared-capacity, service restart, cancellation, lost-acknowledgment and current-authority tests. Update contract refinements, generated bindings/directives, CLI/MCP descriptions and owning docs together. A new live inference is justified by an unqualified provider/profile/API boundary, not routine metadata edits. Source adapters and component-storage formats have separate owners and explicit bounds. No dependency or owned patch is added for this service.

The private memory-binding adapter uses the same authorized `guidance.read` and work readers, with the shared central-project association resolver. If guidance capture representation, byte storage or authorization changes, update that adapter and its denial-before-byte-access, corruption/range, historical-source, association and restart tests together. The adapter may validate an authorized immutable body omitted by a response budget; it cannot use another operation's permission or a guessed body reconstruction. Update both TypeScript declarations and bounded input refinements/local schema definitions before generating the shared catalog. No external provider or dependency is introduced by these bindings.

## Storage and session-hook changes

A storage-format change requires an explicit private plan/backup and isolated all-history migration/recovery qualification before live use; follow [storage maintenance](../reference/storage.md#explicit-migration-and-recovery). Publish a matching source/catalog, quiesce only Moment, and retain the original owner credential custody. Never use an exact Codex release pin as a substitute for validating the consumed boundary.

The shared session hook runs a small entry point that loads the service/provider only after a positive private enrollment hint. Native session configuration uses `memory.configure`; new sessions stay off. Changing the host command or status/context metadata changes Codex's trust hash and needs ordinary native review. A qualified `config/batchWrite` with `reloadUserConfig: true` can refresh loaded thread hook definitions without restarting Codex. Inspect the actual loaded hooks and an admitted input afterward; file writes and reload acknowledgments alone do not establish working capture.

## Capture adapter and memory renderers

The exact-sharing adapter is an optional Darwin consumer of the platform-provided /usr/bin/python3 (Python 3.9 or later) and native clone/birthtime/rename APIs. The qualified host supplies Python 3.9.6 through Command Line Tools. Ordinary read/publication and portable checks do not install Python or invoke a capture effect. Use mise for project-managed runtime dependencies; do not replace the owner’s platform Python, upgrade global tools or infer portability from a version label. Qualify the actual native calls and bounded protocol on each supported platform. Unsupported metadata or APIs refuse without a copy/hardlink fallback.

After Python/SDK/OS changes, run the owning capture tests, including full byte/metadata equivalence, nanosecond/inode precision, protected content, cooperative custody, path guards, interruption and exact retry behavior. The trusted Python adapter is included in the generated source digest. Its internal scheduling/test adapter is never selected from a model-supplied plan. Preserve unknown operation journals before any replacement and recheck remaining custody.

Memory input renderer 2 removes repeated locator/selection metadata from the model presentation while preserving complete text, attribution, source-session identity, relevant timestamps and context links. Exact original request/profile evidence remains retained. Renderer 1 remains reconstructable with its recorded profile; never reinterpret an old rendered-input digest using a new renderer. Native memory profile 6 keeps the same output contract as profile 5. Retained profile 5 completion can reconcile only with its frozen preparation and matching input/instruction/output-contract identities; settlement preserves its original provider and evidence. Current profiles and historical qualified profiles are distinct.

A capture-manifest schema change requires a deliberate schema-version/read-compatibility decision: immutable admitted local.capture-manifest versions cannot be overwritten with a different digest. Regenerate bindings after changes to contract/refinement, runtime or the native adapter; verify installed method descriptions and CLI/MCP projections together. Operator-only JSON surfaces do not imply callable destructive MCP methods.
