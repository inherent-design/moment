## Codex isolation

The current opt-in MCP check resolves the installed executable read-only, generates its actual experimental schemas and launches a dedicated stdio app-server with private HOME, CODEX_HOME, XDG, temporary and workspace roots. It does not inherit Codex/OpenAI/ChatGPT configuration variables or contact a primary control socket. The emitted Moment launcher comes from the actual `IntegrationPort` installer in owned roots. A separate unauthenticated thread discovers and calls the SDK bridge before authentication; host-issued preflight calls are not counted as native model work.

External authentication reads a private, user-owned regular source through `O_NOFOLLOW`, bounded to 64 KiB. Only its current unexpired access token/account pair reaches `account/login/start`; no auth cache is copied, no refresh token is supplied and server refresh requests are refused. `account/read` must show no inherited account before login. Ephemeral auth must leave no `auth.json`. This experimental path is pinned to Codex 0.167.2; qualify a changed version before inference. [Official app-server authentication](https://learn.chatgpt.com/docs/app-server#authentication-endpoints)

The test uses the installed default model and no child model override. A random byte-file digest, length and nonce are admitted as evidence in a restricted fixture incident; their actual values are withheld from prompts. The parent must retrieve them through MCP and submit a schema-valid atom under the selected delegate. A real first turn must appear in persisted history. Both owned components are restarted, the same thread and system resume, the observation survives, and reload is followed by actual discovery and tool use. Exactly one native child must make its own attach/read/write calls, confirmed by child-attributed events, matching persisted call IDs and the exact resulting atom. Inherited parent history alone cannot satisfy the child assertion.

One diagnostic run established that `approvalPolicy: never` with the fixture's read-only host sandbox refuses write-capable MCP tools before Moment admission. The test explicitly sets `mcp_servers.moment.tools.moment_graph_transact.approval_mode="approve"` only on its owned app-server, retaining Moment's restricted grant and policy. It leaves the advertised destructive hint intact. A final model message claiming submission cannot establish admission; actual MCP results and durable graph readback must agree. [Codex MCP approval settings](https://learn.chatgpt.com/docs/extend/mcp#other-configuration-options)

The earlier dynamic-tool native check remains available as `pnpm test:codex-native`. Its two actual tools used a real verifier receipt and retained the observation after a Moment restart. It is baseline evidence, distinct from G5: it does not establish the SDK MCP path, persistent native resume or inherited child propagation. Ordinary checks invoke neither native script. Subscription inference is outside Moment's fixed verifier zero-model reservation; these checks do not measure inference cost or implement a general model-execution provider.

A malformed private authentication source was also refused before inference without echoing its marker or source bytes. Cleanup removed 1,019 files totaling 12,690,691 bytes from two identified, retired probe/schema roots; no active work, pending execution/schedule or unattributed temporary material was removed. Successful native runs close their retained process handles and remove their own roots. The measured cleanup and selected failures are retained centrally.

## Tooling and check interpretation

The continuity guidance following `e860c2126fda38209e74b045379948c61037f8d8` adds no runtime primitive, personal schema, enforced writer ownership or automatic adoption behavior. It records goal-boundary adoption and the preferred use of direct versus durable communication using existing APIs. `pnpm check:types`, `pnpm check:bindings`, `pnpm check:docs` and `git diff --check` passed for this documentation candidate; the full lifecycle and inference suites are not rerun under the continuing no-restart instruction. No active project goal, agent, daemon or installed MCP instruction payload is changed by this documentation update.

An installation follow-up reproduced Codex configuration normalization with an existing server's nested environment table. Empty staging now generates only Moment's entry; supported CLI reads validate the combined configuration, while exact receipt-block removal preserves unrelated bytes. All 14 installer cases and `pnpm check:types`, `pnpm check:bindings`, and `pnpm check:docs` passed. The added case covers both final-newline variants, preview, apply, repeat and removal. This follow-up uses configuration-only checks and static checks; the lifecycle and inference suites are not rerun during an operation that explicitly forbids restarts. Earlier full-suite/native evidence remains scoped to its recorded revision and catalog.

The optional mise `secrets` profile was parsed and its tool pins selected without decrypting credentials. No encrypted Moment secret, recipient custody, or real-key recovery has been established. SOPS/age remains optional until a concrete consumer needs it.

The documentation checker validates local links, anchors, fenced blocks, whitespace, titles, and method-table coverage. Its earlier temporary broken-link and method-drift probes were rejected as expected. It does not validate external website availability or semantic equivalence of prose and code. Type examples reject unguarded mutation, generic policy activation, invented success, forged identity, executable policy, unsupported retry justification, mismatched parameters, client identity injection, and implicit full-record projection access.

The required [M1–M4 and E15 acceptance cases](implementation.md) have been exercised. Exchange/artifact operations, automatic support propagation and M5 additional providers remain unimplemented or deferred. The actual self-use incident complements the synthetic conformance fixtures; neither implies general workload quality. Provider recovery is demonstrated only for this fixed local verifier. Live inference is demonstrated for the explicit bounded native check. No hostile-code OS isolation, workload-quality, general cost, or performance claim follows from these checks.
