# Moment implementation goal

Implement the complete [purpose and guidance package](../reference/purpose.md) on Moment's existing local kernel and native-agent integration. Preserve the user's native coding-agent workflow and central personal store. Complete P1 through P10 and C01 through C32 in [the single implementation sequence](implementation.md#purpose-and-guidance-package), preserving the verified M1–M4 baseline and its required acceptance evidence. This tracked document is a reusable reference template; a runnable personal copy belongs centrally and remains inactive until explicitly invoked. Completing only an initial slice does not satisfy this goal.

## Outcome

A user can retain finite or maintained purposes, extract reusable guidance from selected prompts and actual user decisions, discover applicable targets and local refinements, assess meaningful divergence, and carry useful learning into future goals. Agents can resolve concise source-based instructions, run bounded native work, coordinate guarded repairs, rest without model polling, and recover after interruption. Shared contexts/systems preserve provenance and current authority. Native objective replacements are separately authorized and actually read back; central text or a resume operation is insufficient.

Apply the [native-agent service boundary](../reference/purpose.md#agent-runtime-and-service-boundary). The native agent selects relevance, retrieval depth and strategy using its full working context and other tools. Moment's tools expose durable meaning, source scope, coordination and guarded operations. Treat successful partial reads, selection coverage, readiness to act, and purpose satisfaction separately. Current byte defaults are operational choices to validate against consumers; preserve identity, permissions, explicit omissions and actual hard bounds while allowing the agent to recover further material.

Use the complete system for a real improvement to Moment itself: retain exact sources and accepted meaning, retrieve applicable guidance, admit bounded work, make and verify the change, survive an owned service restart, and retain useful generalization/next action. Implement all seven evolution operations, selected source adapters, the qualified bounded Codex provider, shared guidance projections/local-system exchange, and their operational/recovery behavior. Additional VM/graphical or paid-provider implementations remain conditional on an actual consumer and existing authority; their honest capability/refusal behavior is required.

For any real Codex usage in tests or verification, use an isolated, separate CLI app-server instance with its own transport, configuration, state, and working directory. Preserve the owner's primary daemon, Codex installation, existing threads, and agents. Use the installed executable read-only; do not upgrade it or send test work to its primary daemon. Authentication must not share writable session or refresh state with the primary instance. A protocol-only probe may run without inference credentials; live inference requires a separately qualified supported authentication path. Stop only processes owned by the test.

Read [AGENTS.md](../../AGENTS.md), [the documentation map](../README.md), and the contracts needed for the current unit. Inspect the actual implementation and saved central checkpoint before selecting work. Continue existing implementation before inventing parallel replacements. Preserve the broader model while delivering a connected useful capability at each step.

When invoked from a saved central copy or a shared working directory, resolve the Moment repository through the incident's project association in the central registry. Run repository commands from that checkout. The saved intent's adjacent checkpoint owns task continuation; the directory from which Codex was launched does not redefine the target project.

## Working method

Choose reasonable engineering defaults from the contracts and current evidence. The owner supplies direction and anecdotal feedback; they need not design every type, rule, or algorithm. Record consequential decisions and remaining uncertainty in the owning document. Ask only when available evidence cannot settle a choice that materially changes authorization, scope, external commitments, or irreversible behavior.

Continue autonomously through implementation, debugging, verification, documentation, and the self-use exercise. Do not stop after a plan, a scaffold, or a successful type check while a required outcome remains. Use local development and existing authenticated tools within the authorized task; new paid services, external publication, and unrelated host changes remain outside this goal. Prefer the existing Codex interaction and supported local tooling over creating a second paid inference loop.

For each unit, identify the observable outcome, exact boundaries, negative cases, and completion check. Implement, run meaningful checks, inspect the combined diff, and reconcile the reference docs with the result. Correct contract defects when implementation exposes them, updating types, semantics, examples, and affected acceptance cases together. Do not preserve a flawed draft merely because it exists.

Default to one working agent. Delegate only an independently useful investigation, isolated implementation, or fresh review, within the current user's budget and workspace constraints. Additional agents are a response to useful parallel work, not a required stage.

Keep facts, interpretations, evidence, and authority distinct. Generated policy can activate autonomously inside existing delegation after its required checks. A candidate cannot authorize its own expanded permissions. Preserve full-access host behavior where the owner has selected it while representing actual sandbox boundaries honestly. Measured telemetry controls admission; guesses and model confidence do not count as resource or correctness evidence.

## Continuity and adaptation

Maintain one task-centered checkpoint in the incident's central directory: goal, current revision, consequential decisions, evidence, blocker, and next useful action. Preserve exact identifiers, commands, errors, and unresolved choices across compaction. Reference primary artifacts rather than repeatedly summarizing summaries. Reload only context relevant to the next action.

Respond to evidence and current conditions. Explore when alternatives would resolve uncertainty, investigate when a premise is missing, consolidate when independent work overlaps, verify when a result needs external support, and implement when the contract and evidence are sufficient. These are available behaviors, not mandatory slots. When progress awaits an external condition, preserve continuation state, release resources, and use an explicit wake condition or an honest handoff. Respect user decisions to complete, cancel, or redirect the work.

## Documentation and storage

Keep one owner for each contract. Fold completed reviews into that owner; remove duplicated or superseded transient narration. Retain concise reproducible evidence and recovery inputs. Keep active goals, checkpoints, and captures under the resolved personal store, exposed through `~/.moment`, and keep touched repositories free of required Moment metadata.

Maintain dependency and patch procedures as dependencies are introduced. Document coupled updates, exact upstream versions, local patch rationale, revalidation commands, and removal conditions. Add scripts only for repeated or consequential work, with clear errors and bounded output. Keep project contracts and ledgers in their existing owners; Moment supplies applicable shared targets, evidence and current personal continuation without introducing a universal project layout.
