# Direction

Moment supports sustained software development and investigation while retaining the native interaction of an existing coding agent. The user supplies direction and experiential feedback; agents can derive structures, propose policy, refine prompts, and implement changes without requiring the user to design every mechanism.

The [agent-runtime boundary](reference/purpose.md#agent-runtime-and-service-boundary) makes this division explicit. Codex or another qualified native host supplies the agent's working context, reasoning environment, and native execution controls. Moment contributes shared durable purposes, relationships, source-based guidance, evidence, coordination, and governed operations. Public tools earn their place through those semantics; their availability creates no requirement to persist ordinary conversation or duplicate existing host tools.

Agents choose how deeply to retrieve information and combine it with their other context. A valid bounded read can return metadata, selected records, and explicit omissions; sufficient context for an action remains a separate judgment. Read defaults and ceilings are operational choices to evaluate against actual consumers, independently of model context-window size. Permission, provenance, identity, concurrency, and actual resource bounds remain enforced by the service.

The complete [purpose contract](reference/purpose.md) encapsulates this direction as preservation of meaning, applicable expectation discovery, evidence-based reconciliation, capable participant coordination, and useful learning across goals. Reusable desired relationships acquire project/task-specific bindings and assessments; they are not compulsory workflow stages. [Guidance](reference/guidance.md) and [work](reference/work.md) own the complete proposed execution and API boundaries. Their implementation remains separate from the current kernel and managed surfaces.

An incident is a semantic unit in a context. Depending on perspective, it can appear as one interaction or expose a system of participating incidents. Its identity persists across summaries and execution attempts. Relationships make evidence, dependencies, scope, and interpretation accessible without loading every participant's full history.

Behavior follows conditions. A complex matter may benefit from independent exploration, comparison, consolidation, verification, and execution, but those are possible responses rather than mandatory workflow slots. Ordinary conversation should remain ordinary conversation. Durable purpose can rest while waiting for relevant evidence or capacity.

Moment should run locally, spend only within configured budgets, and keep idle activity inexpensive. Existing coding subscriptions and API billing are separate resources. A model may help author policy or choose a prompt; an idle scheduler does not need a model call. Existing session content and arbitrary workspace files enter through scoped imports rather than automatic whole-host ingestion.

The initial contracts cover a local single-writer store, typed operations, per-incident authority, delegated execution, reactive scheduling, and explicit exchange between systems. Runtime persistence, Codex integration, and sandbox execution are incremental implementations of those contracts. The first useful release uses a local service and native client; additional infrastructure requires a demonstrated consumer.

Human-facing state lives in one personal store, exposed through `~/.moment`. Projects remain free of required Moment metadata. The framework can associate multiple repositories, worktrees, sessions, and runtimes with one context while preserving their separate identities and permissions.

The managed architecture uses MCP delivery for native tool availability across configured Codex sessions and their agents. Moment's own bindings connect implementation, schemas, directives and provenance; machine discovery and human CLI views derive from the same facts. Installation makes the surface available; adoption into ongoing work happens separately at a canonical goal change or deliberate handoff. [Managed integration](reference/managed-integration.md) describes the implemented boundaries and acceptance scope.

Projects retain their own specifications, tracking, ledgers and working conventions. Moment preserves the relationships and selected evidence needed to continue work across those differences. Prefer direct inter-agent communication for brief coordination and Moment for durable structured handoffs and reusable instructions. Choose persistence for expected future retrieval, verification or reuse, rather than message length alone. Existing goals and agents continue until a suitable handoff; no bulk adoption or mandatory project format is implied.
