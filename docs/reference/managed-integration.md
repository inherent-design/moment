# Managed agent integration

This document owns the managed MCP boundary, operation bindings, attachment, service lifecycle, installer, and human presentation. Bindings, lifecycle, attachment, SDK stdio, agent/human commands and the explicit-root installer are implemented. The kernel, native client, and foreground service remain available as described in [protocol](protocol.md) and [integration](integration.md). Installation is explicit; actual local loading and its limits are recorded in verification. [Implementation](../development/implementation.md) and [verification](../development/verification.md) own delivery status and actual acceptance evidence.

## Responsibility and initial scope

Codex owns model turns and native agent creation. Moment owns semantic state, permissions, evidence, scheduling, and effect recovery. A lightweight MCP bridge serves a configured Codex client and connects to one shared Moment service. Multiple bridges do not create independent stores or writers. `moment agents` and human commands project the same operation and outcome facts. The binding catalog is an internal Moment module, not a separate product or an executable language supplied by agents.

The first target is the current Unix/macOS host and the pinned Node/pnpm toolchain. Use stdio only; HTTP hosting, OAuth, a browser UI, graphical/VM providers, peer exchange, a universal artifact store, and a replacement coding harness remain outside this upgrade. Real user installation is explicitly deferred; installation acceptance uses test-owned roots.

## Binding catalog and provenance

`OperationBinding`, `CatalogIdentity`, and the managed boundary types in [the declarations](../../contracts/index.ts) own public shapes. Each operation binds a stable ID/version, availability, input and output schema references/documents, effect categories, retry identity, preconditions, concise guidance, directive identities, and repo-relative source digests. `AdvertisedBinding` requires implemented availability. Descriptive metadata and MCP read-only hints do not authorize effects.

Keep TypeScript as the owner of boundary names and shapes. Extract the existing input schema definitions and semantic refinements into the shared binding/schema owner rather than copying them into the bridge. Generate output shape schemas from the checked TypeScript contract using a dev-only `typescript-schema` alias pinned to `npm:typescript@6.0.2` and its verified JavaScript compiler API; unsupported types or unresolved references fail generation rather than degrading to unconstrained data. Reuse the admitted primitive constraints where applicable. Runtime output validation, type examples, coverage checks, and public execution cases must catch divergence between schemas and implementation. The trusted local registration maps IDs to installed handlers; serialized catalog data cannot select an arbitrary module, shell command, or code path.

Generate self-contained JSON Schema documents, MCP definitions, native client descriptions, `agents` records, and stable instruction fragments deterministically. Hash canonical content excluding its digest field. Include contract content, source-file closure, directive identities, and operation metadata in the catalog identity; exclude timestamps, personal paths, credentials, runtime policy, and live incident state. A dirty tree has its actual content identity rather than falsely claiming an unchanged Git revision. Catalog and per-schema changes require new digests. Identical inputs produce identical generated bytes. Include the exact generator dependency/lockfile identity in the source closure. Keep the existing TypeScript 7 checker; the extra library is for schema generation only. Build/check tasks detect stale generated material; ordinary checks never rewrite it. Runtime startup also checks the installed source closure against the catalog before opening a store or serving tools. Only reachable local schema definitions are shipped, keeping unused definitions out of discovery.

Keep declared future operations addressable as unavailable metadata when specifically requested, but omit them from callable tools and the implemented RPC list. `bindings.discover` reports the configured bridge's `exposedOperations`; implementation, exposure, current policy eligibility, and permission are distinct. The daemon's optional catalog/instance fields in `system.describe` become required for managed readiness. A bridge whose build/catalog differs from the live daemon refuses effects and reports incompatibility. It never replaces a live installation implicitly. Raw legacy RPC remains available for explicit inspection and recovery.

`moment agents [operation-id] [--limit N] [--cursor CURSOR]` emits versioned NDJSON: one manifest and bounded operation records. Default output is concise metadata; selecting an ID yields its exact schemas, semantics, retry rules, and source references. Pagination is bound to the catalog identity and profile, with a default limit of 20, limits 1–100 and a maximum 256 KiB response. Discovery can run offline from the installed build, without creating a store, starting a service, reading private credentials, or scanning histories. Offline metadata makes no current-eligibility claim.

Preserve the exact logical mutation and retry identity before dispatch. A timeout, disconnect, invalid reply, or internal server error after possible dispatch is `OUTCOME_UNKNOWN` with reconciliation guidance and the retained original request. Do not replace its revision, invent a new key, or automatically replay it. Preserve caller-visible invalid-input faults without collapsing all errors into success or internal failure. If an input/output bound prevents returning full detail, report omission or a recoverable fault, never a fabricated empty result. Response-size failure can happen after commit; durable readback and exact receipt replay distinguish it from a write never admitted.

Keep ordinary frames and input JSON under the existing 1 MiB limit. Tool/schema discovery and context packets have their smaller explicit bounds. Retained ambiguous requests belong in private bounded retry material or the exact caller request; never copy authentication headers into error details, goals, or captures. Cancellation of a tool request does not prove cancellation or rollback of an admitted mutation or execution.

Preflight stdio input using the existing bounded strict JSON parser before handing frames to the SDK. Duplicate keys, malformed UTF-8 and oversized frames must be refused before SDK decoding can discard that evidence. This is framing validation, not a second MCP implementation; negotiation, capabilities and protocol handling remain SDK-owned.

Session memory provides selected-source and assessment reads, reversible focus and configuration with explicit runtime/session selection. It is owner-local and does not create a semantic context or project adoption. Reads report processing coverage, selection and whole-source omissions, and invoke no checker. Focus retains scoped work/guidance references under current authority without activating a goal or enrolling a session. The [session-memory integration](integration.md#session-conversational-memory) owns hooks, operator commands and provider status. The current continuity profile has 25 tools including registered-source candidates; earlier tool inventories qualify only their tested builds.

## Attachment and selected context

Begin ordinary recovery with `workspace.attach` using the known project location or selection. When it returns `needs_selection`, call `workspace.attach` again with the chosen candidate's context and incident IDs. Build the `workspace.read` target with only `systemId`, `contextId` and optional `projectId`/`incidentId` from the attachment; its `principalId`, `grant` and `catalog` are authenticated metadata, outside the routing input. Candidates are alternatives and do not yet supply a complete read target. `includeMessages` is optional and additionally requires `messages.read` authority; a context-only reader can omit it. MCP already advertises callable input schemas. Use `bindings.discover` with an `operationId` when additional operation metadata is needed; unfiltered discovery serves catalog/integration work and returns every exposed binding, including full schemas.

`workspace.attach` is a read-only adapter operation. It accepts optional explicit project, location, context, and incident selectors and returns an `AttachmentResult`. Selection order is explicit context/incident, an explicit project association, then an explicit canonical location/Git worktree association or a trusted host assignment. The bridge's own launch directory is never assumed to be the agent's active project. Without a usable selector/assignment, return `needs_selection`; do not scan the host or guess from window focus. Origins remain hints. Shared launch directory, project identity, containment, and authority stay distinct. Known clone/move handling reuses [project discovery](storage.md#project-identity); unresolved alternatives are never merged. If selectors disagree, refuse them rather than applying a preferred subset.

A location should identify an associated repository or worktree. A container holding several repositories need not be associated itself; lack of a match there does not establish that its individual projects lack Moment context. Supply the actual project location when the task identifies one. Shared launch directories do not choose an incident, and several saved incidents are legitimate alternatives rather than evidence that work has started or stopped.

Read only candidate contexts allowed by the selected credential bindings and current policy. Filter unauthorized alternatives before counting candidates or reporting ambiguity; explicit inaccessible IDs return `NOT_FOUND`. `incident.list` is a new kernel read: it requires its action and applies current `incident.get` admission and incident scope to each row before pagination, including historical pages. Status filters intersect; an explicitly empty set matches nothing. Use existing encrypted, principal/grant/query/snapshot-bound cursors and 1–100 limits. No hidden counts or other actors' mailboxes are returned. Previously saved policy is not expanded during an upgrade; missing authority produces an actionable refusal. Owner-authorized policy updates continue through existing publication/activation.

Choose a context or open/resting incident only when evidence identifies one unambiguous candidate. Return `needs_selection` with up to 20 authorized options and a truthful `more` flag when none or several fit. Candidate labels come from context labels and incident purpose, not invented names. Explicit terminal incidents remain inspectable. Attachment creates no incident, grant, project association, or policy. A new meaningful objective uses the existing context/incident creation tools with agent-generated identifiers; no routine human UUID copying is required. Ordinary conversation need not attach or persist anything.

Attachments are explicit routing references, not bearer capabilities or mutable per-connection current work. `workspace.read` accepts `AttachmentTarget` and rechecks the credential, reference locality, current context/incident access, and each requested detail. It returns a `ContextPacket`: selected context/incident, bounded continuation/evidence, optional recipient messages, current directive provenance, and omitted references. Default selection is 20 records and content is at most 16 KiB; requested `maximumBytes` must be 1–65,536 and `limit` 1–100. Required context that cannot fit returns `LIMIT_EXCEEDED`. Optional visible detail may be omitted with its references; an omitted count must not reveal hidden material. Explicit inaccessible references fail before omission. If a required stored object would disclose inaccessible dependencies, refuse it rather than redacting its bytes under the original digest. Do not load all history, unrelated incidents, all messages, or all project files to attach.

The initial authentication modes remain an explicitly selected owner or existing delegated credential. Codex thread labels, client names, and MCP connections are correlation evidence, not independent principals. Output records the credential's actual principal and grant; multiple sessions using the owner credential share that attribution. Distinct principals require separately issued credentials and admitted grants. Stronger automatic per-agent identity provisioning is deferred; the first delivery must state this limit instead of forging independence. Current `messages` and `prompt.compose` checks remain authoritative.

A missing, invalid, expired or revoked selected delegate credential never falls back to the owner. Service provisioning and connection management do not issue new domain grants or silently migrate policy. Full-access host tools keep their actual host authority; the MCP boundary is not an OS sandbox.

Stable server guidance explains purpose, operation selection, retry handling, and quoted-evidence boundaries. Keep its first 512 characters self-contained. Versioned per-operation instructions and selected admitted prompt templates share catalog provenance; dynamic findings and policy changes are fetched through normal reads without redefining every tool. Generated policy still activates only under current authority. Availability never mandates a swarm, a fixed research pipeline, or a record for every conversation. MCP does not automatically save conversation or intercept compaction; agents retain meaningful continuation explicitly.

The installed `moment.continuity` directive version `5` carries the [goal-handoff convention](integration.md#continuity-between-goals) in server instructions, offline discovery and context packets. Tool descriptions distinguish durable mail from native live coordination, identify continuation updates as coordinated work, and describe prompt composition as rendering an admitted template. These guide selection alongside session memory and registered-source candidate tools in the 26-tool continuity profile; current schemas and admission rules remain authoritative. A new bridge process loads the updated catalog. Existing bridges retain their loaded guidance; refetching their tool lists does not hot-load changed source files. Use a client refresh/reconnection that recreates the Moment bridge. The new catalog identity requires a matching Moment service build; a client refresh cannot upgrade an already running older service, and incompatibility is reported rather than forcing a restart.

When a build rollout is authorized, coordinate the service and its clients: a new bridge refuses an older service, and a cached older bridge refuses a new service. Confirm the discovered catalog and an actual selected read after refreshing, rather than treating a reload acknowledgment as sufficient evidence. Isolated protocol-only checks on Codex 0.169.0 found that unchanged MCP configuration retains its existing bridges across reload and a subsequent turn. Changing the generated `MOMENT_CATALOG_REVISION` environment value and calling `config/mcpServer/reload` replaced the bridges of two existing idle threads without restarting their app-server. The marker carries the catalog digest as a discovery revision, not permission or a security boundary. Those observations do not establish behavior during active work. Hooks use a separate retained thread snapshot. A later zero-inference owned 0.169.0 probe qualified `config/batchWrite` with `edits: []` and `reloadUserConfig: true`: an existing thread then reported the changed hook metadata, without a process restart. This refresh preserves native trust requirements; it does not itself trust a changed hook or prove execution. Earlier tests found that MCP reload and unsubscribe/resume did not refresh an existing thread's disabled hook set, while an owned app-server restart and same-thread resume loaded the new untrusted definition. Coordinate an initial hook rollout and review definitions through the native hook browser; a successful inventory lookup is not proof that hooks executed. See [verification](../development/verification.md#read-packing-candidate-evidence) for the controlled case and limits.

### Recovering selected work

Implicit incident discovery requires `incident.list`; a saved policy can permit `incident.get` while denying that newer action. A discovery refusal does not prove that all project access is unavailable. When a trusted current handoff supplies the context and incident IDs, try that exact explicit attachment under the same credential, then read its returned target. Explicit selection still checks incident, project association and detail authority. It cannot authorize an inaccessible incident, justify guessing hidden IDs, or fall back to stronger credentials. General discovery needs an admitted policy update if it is actually required.

When an existing delegation authorizes policy maintenance, a compatibility update can add the required read action to the applicable existing rule through `policy.publish` and explicit `policy.activate`. Preserve the rule's principal condition, other actions, issuers, limits and parent identity; do not replace a saved policy with a newly generated bootstrap policy. Verify both the intended discovery and unaffected delegated scopes. Publication alone is not activation, and successful enumeration can correctly return several incident alternatives rather than selecting or starting one. Policy data is checked on subsequent calls; this does not require installing a new tool catalog or restarting the daemon.

### Read success, coverage, and budgets

A successful `workspace.read` can return metadata, selected whole records, and `omittedRefs`. The agent combines that result with its native conversation and other tools, then selects further references when its next action needs them. Absence of a next-action record from one response does not by itself make the read fail. Required routing/context that cannot fit, invalid requests, and inaccessible explicit dependencies retain their actual errors.

The installed packet reports omissions through `omittedRefs`; it has no separate metadata-only mode or coverage discriminator. The proposed guided packet's `complete` describes the named authorized selection and source coverage. A metadata projection can be complete while bodies are outside its requested scope; a request for five bodies returning three because of a budget is partial. Neither result certifies readiness to act or completion of the purpose. Additional selection/coverage or omission-reason fields require a versioned, tested contract before advertisement.

| Bound | Owner and meaning |
| --- | --- |
| Model context and history compaction | The native host manages the agent's overall working context. |
| Retained tool output | The native host can independently budget an individual output's contribution to history. |
| Moment response budget | The caller requests `maximumBytes` and `limit` within the installed service bounds. The current 16 KiB default and 64 KiB maximum are implementation choices, not model context limits or measured workload optima. |
| Transport and execution resources | Moment enforces actual frame, dependency-scan, authority and resource limits independently of the caller's preference. |

Codex exposes its own context/compaction and tool-output settings in the [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference). The current Moment read request carries no measurement of the native conversation's remaining token capacity. Future qualified host hints can inform a caller preference without making the semantic kernel depend on one model or a fixed fraction of its window. Changes to defaults or ceilings need consumer evidence about useful retrieval, extra round trips, resource use and task outcomes where observed.

The byte budget includes the full serialized context, evidence support and omission metadata. Inspect `omittedRefs` and request selected details with an appropriate budget rather than assuming omission means absence or irrelevance. A dated entrypoint can locate work without supplying its current next action. Writers can retain a compact continuation and reference longer results, preserving history and source identities. Summaries, excerpts and projections retain their own identity and source basis; a byte cutoff cannot silently replace an original record under its digest.

Packing considers explicit details in caller order, then continuation records in the writer's declared order, then requested recipient messages. An unscoped fallback query retains its query order. Reserve all known permitted omission references before selecting bodies; each included whole item replaces its omission reference only while the final packet fits. A body that cannot fit stays referenced while smaller later items can still be returned. A fitting metadata-only packet succeeds; an oversized minimum packet retains its byte-limit failure. Required explicit access checks precede omission, and limits and packet fields are unchanged.

`workspace.read` supplies a context packet. A known omitted body can be requested with a larger `maximumBytes` or through `graph.query` with an exact ID and a small page. Graph results include the selected record and its support without the context packet's fixed overhead; they retain their own current-authority and transport checks. The 64 KiB packet ceiling is not a universal record-read or model-context limit.

The current MCP bridge refuses a domain envelope larger than 480,000 bytes before projecting it into structured and text results. Reducing a page to one record cannot split that record. If the selected record still exceeds the bridge's bound, retain the explicit refusal and identify a qualified native client, permitted projection or independently accessible source. A source locator requires the host's own access authority and a content-identity check; the continuity profile does not serve arbitrary files or provide generic chunked record retrieval. An omission identifies a recovery lead, not a guarantee that every consumer has a suitable route.

## Service lifecycle and custody

`ServicePort.inspect` is observational: an absent store yields stopped/uninitialized state without creating files. `ensure` resolves the existing home rules, starts the installed service when needed, and performs an authenticated `system.describe` readiness handshake. It verifies system identity, service instance, protocol, and catalog before admitting managed calls. Reuse the store's PID/nonce single-writer claim and socket checks. Simultaneous starters elect one candidate through `managedStartup` metadata under SQLite `BEGIN IMMEDIATE`, alongside the existing writer protections. The parent nonce and actual child PID distinguish live, retired and insufficient-evidence startup. Association, retirement and stale-candidate replacement are transactional, preventing a losing starter from reviving an explicitly stopped service. A losing starter waits for authenticated readiness without spawning another candidate. Startup has a configurable, visible deadline with a 10-second default; expiry reports uncertainty and does not kill a process or erase ownership evidence.

MCP initialization/tool discovery uses the installed catalog without creating a store or starting inference. The first domain operation calls `ensure`; observational status and offline `agents` discovery do not. This keeps tool availability cheap while preserving a required readiness/compatibility check before domain access.

Spawn the shared service detached from the bridge with a private bounded diagnostic log, explicit executable/arguments, resolved home, and the required environment only. A closing bridge releases its own connection, not another session's service, provider, or pending work. Idle operation invokes no model and uses existing event/timer maintenance. A crashed service is restarted on the next managed connection after conservative ownership validation; retained schedules, receipts, credentials, and unknown effects survive. Live or indeterminate ownership, an incompatible database/catalog, and an unowned socket produce refusal with inspection guidance, not cleanup or replacement.

The daemon instance nonce is fresh at each start. `service.stop` accepts that exact nonce, requires the local owner with no delegated binding, and acknowledges only that graceful shutdown was requested. The server sends the acknowledgment before draining/closing. The manager observes actual retirement separately; providers retain truthful receipts or unknown outcomes. A stale nonce cannot stop a newer instance. Stopping is an explicit operator action and never sends a signal to a remembered arbitrary PID.

This delivery provides on-demand startup and continued operation while the host process survives. Logout, reboot, and a stopped host can suspend timers; persisted wakes are reconsidered when service starts. An always-running login/startup service and guaranteed wakes while no service runs are outside this first installer. No real user service registration is authorized. Keep authoritative database, credentials, retry/recovery material and provider receipts distinct from caches and disposable logs. No repair operation deletes all state or adopts ambiguous ownership.

The command set is intentionally small. Existing raw `call`, `credential`, `verifier`, and foreground `serve` remain operator interfaces. The commands below are implemented. Installer acceptance uses explicit test-owned roots; actual user installation remains deferred:

| Command | Question answered and behavior |
| --- | --- |
| `moment mcp` | Codex-facing stdio bridge; managed startup with a negotiated catalog. |
| `moment agents [operation-id]` | What can this build do, with which exact inputs, effects and recovery rules? |
| `moment status [--context ID] [--details] [--json]` | Service health, visible active/resting work and what needs attention; observational by default. |
| `moment show INCIDENT --context ID [--details] [--json]` | Purpose, current outcome/reason and selected continuation for one incident. |

Human rendering leads with outcome, relevant reason, and an available next action. Details retain exact identities, checked scope and provenance. Machine output preserves typed facts and failures with no terminal controls or progress on stdout. Use familiar words and show missing input, empty work, no-op, partial completion, conflicts and recovery accurately. Never hide the essential reason behind a details hint or invent an unimplemented full-check command. Fast local reads need no spinner. A slow command owns one temporary progress region, clears it before its one final report, and shows actual phases/counters; redirected output is sparse. Test real PTYs where rendering changes. An interruption does not turn completed effects into failure or erase cleanup problems.

`IntegrationPort` implements connect/disconnect with explicit absolute target roots and a preview default. Generate an exact launcher using the installed pinned runtime and checkout, resolved Moment home, `MOMENT_CATALOG_REVISION` set to the generated catalog digest and an optional credential-file locator; tokens never enter TOML, argv, output or receipts. Use Codex's supported MCP CLI in a test-owned staging `CODEX_HOME` to derive the configuration change, verifying that only `[mcp_servers.moment]` changes and unrelated bytes/comments remain intact. Do not maintain a second permissive TOML rewriter. Before publication, lock cooperating installers and revalidate the target's content/identity against its expected-old observation. Reject observed external edits. This does not claim atomic coordination with non-cooperating configuration writers; require a quiet configuration during apply and document the boundary.

Retain a private installation receipt under the selected Moment home binding the canonical target, launcher/catalog identity and owned entry digest. A different preexisting `moment` entry is a conflict, not permission to overwrite it. Repeating an unchanged owned registration is a no-op. Disconnect removes only an entry matching its owned receipt; user edits or missing ownership require inspection. Interrupted configuration/receipt publication has a narrow recoverable journal and explicit recovery result. Do not retain whole user configuration or secrets in ordinary receipts/captures. Removing integration never deletes the database, credentials, goals, or provider evidence and never stops a service still used by other clients.

## Running the implemented surfaces

Use `pnpm moment agents` for concise versioned NDJSON, or `pnpm moment agents workspace.read` for the exact selected schemas. Default discovery lists implemented operations; explicitly selecting a declared-only operation explains its unavailability. Catalog source closure covers actual runtime, generator, contract and lockfile content; each operation separately names its owning sources. Offline discovery and `pnpm moment status` leave an absent home absent.

`pnpm moment mcp` serves the default 25-tool continuity profile. The optional `--profile operator` exposes additional installed domain operations; it still excludes service stop and installation. Initialization and discovery do not start a service. The first domain call starts the shared service; closing the bridge leaves it running. `pnpm moment show INCIDENT --context CONTEXT` retrieves selected purpose/continuation, and `pnpm moment stop` requests the current owner-bound instance and waits for confirmed retirement. Use `MOMENT_HOME` and, when delegated, `MOMENT_CREDENTIAL_FILE` to select custody explicitly.

`workspace.read.target` contains only routing fields: system/context IDs and optional incident/project IDs. Copy these fields from an attachment; do not submit its attribution/catalog fields as authority. Packets default to 20 records and 16 KiB, support up to 65,536 bytes, and admit at most 256 distinct dependency checks. JSON/NDJSON views are plain machine output. Human views use the same outcomes without an idle spinner.

MCP negotiation and framing remain SDK-owned after strict UTF-8, duplicate-key, depth and frame preflight. Input schema validation runs through Moment’s shared validator so its exact domain fault is returned in the structured envelope and identical text fallback. The bridge permits at most 32 active calls and bounds a serialized envelope before duplicating it into the two result forms. Large ambiguous requests are retained privately in `runtime/retries` with exact content identity and a 64-file envelope; interruption leaves publication evidence for inspection. A full or interrupted retry store never causes automatic replay or eviction of unresolved work.

Registry and owner identities are published as complete private files using exclusive links. Retained databases with missing owner custody refuse replacement. The tested macOS runtime accepts Unix socket paths through 104 bytes and rejects 105; overly long central roots receive an actionable refusal before startup. A shorter storage location requires preserving the existing central state, never reinitializing it. Other platforms have not been qualified by these tests.

## Installation preview and recovery

`pnpm moment connect --codex-home /explicit/codex --moment-home /explicit/moment` previews the exact owned TOML entry and launcher without creating either target. `--json` returns an `IntegrationEnvelope`, including the launcher and owned-entry content/digest for review. The explicit `--apply` operation publishes only the supported Codex CLI’s verified staged change. It uses the actual Node 26.13.0 executable and this checkout’s CLI; optional credentials appear only as a file locator in the emitted environment. Neither command invokes inference, reloads a running client or registers a login service. Real installation is a separate user operation.
