# Executable semantics and proof boundaries

`core/semantics.bend` owns the executable definitions currently used for three-valued condition composition, deny/permit precedence, budget/deadline bounds, reference equality, grant-chain admission, conservative policy narrowing and immutable record/assertion admission. It selects declaration-first graph order while preserving support-command order and withdrawal identity. The native adapters in `runtime/semantic-core.mjs`, `conditions.mjs`, `authority.mjs` and `graph.mjs` encode observations, perform storage lookups, invoke the generated decisions and apply selected effects. Transactions, persistence, authenticated observations and provider effects retain their explicit native owners.

`runtime/generated/semantics.mjs` is the emitted executable. `semantics.json` identifies its exact core, model, checker and toolchain inputs and output digest. The public binding catalog also covers these inputs and the generated executable. Editing generated JavaScript or a covered source without regeneration refuses qualification. A manifest establishes identity and coherence; it does not claim that a proof or native test ran.

Kernel admission executes the same core for operator classification, action/resource/incident intersections, context-wide delegation, stale mutation basis, incident lifecycle/evidence and graph query selection. A matching owner identity with a bound grant remains delegated. Empty delegated chains confer no access. Core method admission is only a prerequisite: the native handler still loads and evaluates the current policy and validated grant ancestry before replay or effects. Scope caches belong to that one admission snapshot and never survive a new current-authority check.

Native ports load authenticated principals, actual grants, policy issuers, records and accessible support. They preserve exact reference keys and decimal safe-integer revision identity without narrowing either to a word. Query selection retains explicit empty filters, independent visible support and role-specific connectivity. Native JSON-pointer projection, string ordering, encrypted cursors and storage pagination apply the selected representation; selection cannot manufacture authority or hidden support.

`core/control.bend` owns projection field/grouping admission, proposal shape and identity admission, exact commit bases, combined execution-plan identities/incidents, transition branch visibility, control namespaces, grant actions/revocation, schema identity and binding-name admission. Selected bound-grant checks have one core owner shared by capability and kernel consumers. Native ports decode JSON Pointers, measure the same field/execution arrays, compile schemas, read current objects and policies, apply selected projections and commit effects. The pointer codec is included in the frozen source closure. A supported root pointer exposes only the already authorized stored record and adds no assertion support.

Control models include useful fresh proposals/commits and root projections alongside stale bases, aliasing, hidden schema fields and delegation branches. Lean's schema theorem assumes its stated prefix observation; finite comparisons and the Bend literal-prefix law independently exercise actual prefix implementations. The model's acceptance theorem requires the recorded and current revision/policy identities to match; actual current authority, authenticated observations, atomic storage and receipt recovery remain separate native obligations. A valid proposal does not activate its own rules or authorize an external effect.

Reaction source cutoffs, visibility-before-type selection, eventless mode and three-valued observation progress also execute in the core. A positive observation selects a candidate while unresolved earlier observations remain meaningful until that match; false evidence alone cannot resolve them. Exact two-word sequence comparison owns ordering even at large counters. Native ports fetch immutable events, establish their actual visibility, apply the selected order, evaluate the condition with current scoped queries, bind actual values and validate the destination schema. Candidate selection executes no destination. The generic matched-trace theorem and finite observation traces qualify their stated model; native event access and eventual execution retain separate admission.

`core/awareness.bend` owns detail/mailbox boundaries, recipient discovery, reply participants, retention/summary limits, message selection/order, template identity/support, slot admission and optional evidence selection. Native ports observe records, current policy and source access, parse template markers, render canonical JSON and measure actual UTF-8 bytes. The core selects each optional omission in reverse declaration order; required sources are authorized before any omission. A template's support must come from a current admitted issuer with readable dependencies. Rendering creates neither execution authority nor proof that an agent inspected the resulting evidence.

The same core owns bounded event visibility, including every pop, repeated visit, alternative requirement group and requested reference observation. Groups remain independent: partial access across different alternatives cannot combine into one permission. The native demand port fetches only requested immutable events and checks each requested reference freshly. Its event cache contains bytes and identity, never a retained permission result. Empty groups supply no authority, and missing/foreign events or an exhausted 64-pop budget refuse visibility. Legacy explicit visibility references retain their meaning, including an explicit empty list. The native event producer observes admitted effects and preserves their per-subject alternative requirements; it cannot weaken the core's reader admission.

Finite visibility comparisons exhaust directed graphs through two nodes under the named missing-event, foreign-context, readable-reference, group and operator products. That model uses fixed readability for each run; actual tests separately exercise changing permission observations, lazy short-circuit behavior, exact budget boundaries and real delegated historical reads. Authentication, actual source/byte observations, native marker and JSON codecs, cryptographic cursors, publication and wait transports remain named trust boundaries.

`core/policy-query.bend` owns authorization-query snapshot/provenance budgets, scoped issuer projection, effective support, relationship selection and bounded breadth-first traversal. The budget is shared across the query callbacks of one policy evaluation. Native ports supply the current immutable snapshot, admitted issuer set and current scope observations; they use core-selected identities and indices to construct the trusted query view. Literal relationship operands must have string reference identities in the current namespace before canonical key encoding or scope lookup. Malformed or foreign operands remain unknown, including existence-query endpoints.

Relationship role payloads are decoded only for the core-selected affordable edge prefix. An omitted suffix has an explicit unknown sentinel. The native codec supplies role lengths from the same immutable arrays using exact two-word counts; it does not convert a potentially oversized natural into a wrapping word. The complete-graph model independently counts its lists and charges observations in breadth-first order, then compares with the actual prefix/codec path. Already observed positive evidence survives an omitted suffix; a restricted negative or exhausted budget supplies no proof. A node-limit result preserves any independently usable remaining budget. Native source authenticity, array-length observations, snapshot assembly, generic query observations and compiler translation remain trust boundaries.

`core/execution.bend` owns execution state/action selection and terminal classification. Native execution adapters validate actual provider, lease/fence, evidence, schema, usage and current authority before applying selected state. A claim selects leased work and requires fresh authority; it does not establish dispatch. Positive effect completion requires a dispatch heartbeat. Cancellation preserves an actual later result, and unknown work remains unclaimable until separately justified reconciliation. The model compares every declared state/action pair and all two-step traces; actual lease/provider/persistence tests qualify the separate bridge. A supplied `lost` or `observed` signal is not evidence that loss or an outcome occurred.

`core/capability.bend` owns advertisement selection/publication, exact schema/version/feature/isolation compatibility, grant-resource intersection, missing-incident qualification and ranking. A compatible candidate requests a policy observation; it cannot become eligible merely because that observation is missing. Unknown policy remains unknown, denial is ineligible, and a later policy result cannot erase incompatible or missing-scope evidence. Empty scope chains confer no matching authority. The native adapter validates current grant ancestry and observes actual current policy only when the core requests it. Its generic array sort applies the core's eligibility/count/identity comparator without supplying another rank policy.

The same owner composes execution visibility, bound-grant/reviewer selection, reconciliation access, attributable-source requirements and live context/incident/advertisement admission. Expiry and deadline leaves use the existing exact ordered clock representation. Native schema compilation, source lookup, profile/provider validation and measured outcomes remain required ports. Lean proves the stated eligibility/policy, visibility, evidence and reflexive-order properties; finite structured comparisons and real current-policy/expiry tests qualify their bridge. Advertisement compatibility and an isolation label establish neither permission to dispatch nor a physical sandbox.

The core also owns lease-window minima and exact interval subtraction, boot/frame expiry, lease credentials, fencing increments/comparison, retry admission, execution maintenance and timer selection. Current grants/advertisements/deadlines supply the window bounds; missing or changed clock frames expire a retained lease. Terminal maintenance is inert. Active expiry becomes uncertainty and cannot by itself admit another claim. Cancellation bars retry while preserving observed-outcome reconciliation. Overrun holds and one-slot reservation admission use the same core rather than separate native policy checks.

The native clock port observes a stable boot identity, integer wall milliseconds in the supported four-digit UTC calendar, and a finite nonnegative fractional monotonic reading. It interpolates a selected integer interval into that monotonic frame using native binary64 arithmetic and validates the resulting endpoint. The model proves its stated interval/frame/transition properties; it does not prove a physical clock or arbitrary native floating-point interpolation. Actual fractional-origin, backward-wall, restart, deadline wake-up, high-token and timer tests qualify the bridge.

`core/topology.bend` owns supported-relation projection, exclusive-parent admission, acyclicity and verdict precedence. Structural containment is independent per perspective; precedence is independent per explicit frame, with the context as its default frame. Independent assertions remain independent, and any remaining asserted support keeps a relation active. The native graph adapter supplies every stored record and support, groups opaque identities and encodes indices. It validates the complete graph, including edges hidden from a delegated writer, rather than the writer's visible projection.

Topology admission uses bounded Kahn traversal and checks every original edge against its resulting strict rank certificate. Lean independently specifies bounded reachability for finite comparisons and proves that a valid strict rank certificate excludes every positive path back to its source; subsets inherit that certificate. The theorem is conditional on the stated edge/rank check. It does not prove compiler correctness or that a native adapter supplied every edge. Finite comparisons exhaust directed graphs through three nodes, both parent modes, selected invalid/duplicate inputs, relation projection, verdict pairs and all three-valued rank assignments on three-node graphs. Native checks additionally exercise hidden cycles, independent support, atomic replacement and a long chain.

## Numbers and representations

The native JSON boundary supports finite IEEE-754 binary64 numbers. The codec preserves their order using two unsigned 32-bit limbs, including fractions, subnormal values, negative numbers and both representations of zero. It does not narrow JSON values to Float32 or pass a 64-bit order key through Bend's JavaScript-host `Nat` representation. Native calendar parsing supplies comparable instants in the same millisecond frame; resource comparison does not change units or frames.

`core/accounting.bend` owns exact safe-integer reservation charging, accumulation, capacity and monotone usage. Counts use two unsigned words with a 21-bit high limb. Carry is exact; sums above 2⁵³−1 produce an explicit overflow that fits no finite ceiling. The native adapter exposes that overflow only as an internal accounting sentinel; individual persisted observations remain their exact admitted integers. No rounded sum can admit another request. Current context, policy and ancestor grant envelopes remain separate and all must fit.

Kernel revision preparation and the trusted SQLite commit port reuse checked core addition for context revisions and event sequences. The final exact value is admissible; another increment returns `LIMIT_EXCEEDED` and commits no state, events, outbox or receipt. Reads and authorized exact receipt replay still work after exhaustion. No wrapped counter or unsafe JSON integer can authorize another write. This is a representation ceiling, not an instruction to reset retained history.

Scheduler capacity uses the same core for each envelope's nonnegative remainder and their minimum. Overflow leaves no advertised capacity. Compound outgoing requests are accumulated exactly before their rule envelope admits the atomic commit. Relative event anchors use exact count addition and the native calendar frame's supported bound; zero gaps remain valid, while out-of-calendar results refuse admission. Timer minima share the framed execution selector.

`core/scheduler.bend` owns schedule lifecycle, visibility composition, wake admission, event selection, edges, queue/coalescing decisions, exact occurrence order, cursor acknowledgement and incident round-robin selection. `core/collections.bend` supplies stable text membership, intersection and union. Native ports obtain current authorization, immutable events, event-revision snapshots and query observations, generate fresh identities and commit selected state/events atomically. A selected schedule still needs current rule, policy, grant and destination admission.

The causal core requests each event observation and owns its visited set, stack order and 128-pop budget, including repeated pops. Full subject reference identity distinguishes a schedule from a same-ID foreign reference. Missing, foreign or exhausted ancestry remains unknown. The native loop fetches only requested observations; it supplies no second ancestry algorithm. A full pending queue preserves its source cursor and records the activity revision that caused backpressure. Unchanged blocked work rests; new activity permits another observation before dispatch. A delayed failure cannot annotate a different occurrence or a newer mutation basis.

Lean proves selected cursor/edge, blocked/terminal, unresolved-ancestry and eligible-selection properties in its model. Finite emitted/native comparisons include lifecycle/readiness products, source-order/coalescing boundaries, incident selection and two-node causal graphs. Native cases additionally exercise retained cursors across actual execution completion, intervening cancellations/revisions, multiple incident queues and interacting schedules. These establish neither unconditional liveness nor arbitrary source visibility. Progress requires delivered activity, fair daemon/worker service, applicable authority, available resources and eventual resolution of uncertain dependencies; blocked work cannot satisfy those premises by polling.

Active or uncertain executions retain the greater of their reservation and observed cumulative usage. Terminal unmeasured cumulative quantities retain their reservation; terminal measured cumulative quantities retain observed use. Memory and concurrency reservations are released when execution becomes terminal, while peak memory remains in its individual usage record. An observed overrun remains truthful and blocks new dispatch; it does not become a failed observation merely to fit a budget. This is resource accounting, not a hard operating-system limit or currency conversion. Native byte counts, provider measurements, envelope currency checks and effects remain required observations.

Topology indices and ranks use unsigned words. Logical node/edge counts stay below 2³¹; padded power-of-two arrays are fresh, independent affine storage. The core checks endpoints against the logical node count before array access, whose upstream representation otherwise wraps indices. Node indexing is a representation choice and creates no semantic identity or authority.

Conditions distinguish true, false and unknown evidence. Malformed query output remains unknown, and an unresolved deny blocks a matching permit. The native traversal retains ordered observations and applies the bounded core decision before invoking a query. A missing observation cannot become authority through negation.

## Qualification

`pnpm build:core` compiles with the pinned Bend release from a digest-checked frozen copy of every covered input. It refuses publication if the working inputs changed. Copying also prevents a source edit that returns to its old bytes from producing an executable blessed with the wrong inputs. `pnpm check:core` checks source/output coherence without installing tools or invoking inference. `pnpm test:proof` requires explicitly installed formal tools: it freezes the same source closure and emitted executable, checks Bend's separate kernel verdict, runs the Lean model, audits the declared theorem dependencies and compares the finite model cases with that frozen generated/native consumer. Final source/output disagreement refuses the report. Its output states the qualified snapshot, exercised scope and assumptions.

`core/LAWS.bend` owns Bend law statements and `core/PROOF.bend` supplies their implementations. `proof/Moment.lean` owns the selected Lean model statements and executable correspondence cases. Its explicit axiom-audit declarations identify the claims being checked. Missing audits, incomplete proofs, warnings and dependencies outside the stated standard axiom set refuse qualification. A helper theorem or model outside this declared claim set is not certified by the report.

The finite truth/support comparison exhausts its named input domains. Numeric execution tests compare the actual native and generated representations over selected boundary and generated values. Neither establishes arbitrary external effects, unbounded native arithmetic, freeform model meaning or compiler correctness. Bend's type-theory translation and emitted JavaScript remain explicit trust boundaries; the Lean kernel checks its stated propositions, not their applicability to every program behavior.

Use the [authority contract](authority.md) for acceptance and delegation. A proof report is attributable evidence bound to inputs and a consumer. It cannot change the policy used to admit itself. Preserve old statements and claims when creating a new identity or qualified successor; reading or verifying a candidate does not activate it.

Moment owns its production definitions, codecs, laws and conformance here. The earlier sibling `rules/moment` models are historical experiments and comparison material, not a second canonical runtime or a dependency of fresh clones/packages. Preserve their claims and limitations when redirecting them; do not advance a stale source gate without actual correspondence. Generic cross-project lemmas may remain with their existing owner.
